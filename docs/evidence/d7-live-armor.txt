2. HONEST NOTE - FAIL-OPEN BUG FOUND AND FIXED INSIDE THE WINDOW
====================================================================
The first live call exposed a response-mapping bug in the Day-7 client:
LiveModelArmor looked for decision/blocked attributes that do not exist on
SanitizeUserPromptResponse, so a managed MATCH_FOUND verdict mapped to
blocked=False (fail-open). A raw-response dump proved the real shape
(sanitization_result.filter_match_state + per-filter oneof match_state) and
that the API DID flag the fixture (pi_and_jailbreak MATCH_FOUND, confidence
HIGH). The mapping was rewritten to read the real shape and fail closed on any
unrecognizable verdict (armor_unparseable); a second quirk (proto enums
stringify to their int value) was fixed by reading the enum name. Tests were
extended for both fail-closed paths (18 model-armor tests green). The final
run below is captured with the corrected mapping.
