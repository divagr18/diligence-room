Live deployment evidence — project rebuild (2026-08-29)
=======================================================

WHY A REBUILD
-------------
The original project `diligence-room` (910285417505) entered a
"cached-deleted" state: `gcloud projects describe` reports
lifecycleState ACTIVE, but every Cloud Run WRITE is rejected with

    PERMISSION_DENIED: denied: Project #910285417505 has been deleted

Reads still worked (Firestore, Pub/Sub, Artifact Registry). Both Cloud Run
services had failed revisions (ContainerImageImportFailed / "Image not
found") because their Artifact Registry images had been purged, and traffic
could not be re-pinned to a healthy revision because update-traffic is
itself a write. This is the same condition `live-deployment.txt` recorded
for us-central1 on Day 14; by 2026-08-29 it covered europe-west1 too.
Reconciliation is Google-side and unbounded, so the stack was rebuilt in a
new project.

LIVE REPLAY (the beat-3 path)
-----------------------------
  scripts/video/replay_cli.py gained --live (opt-in; refuses if
  FIRESTORE_EMULATOR_HOST is set, and defaults to its own deal namespace).

  run: --live (deal-falcon-demo)
    run_id=replay-bdd640fb0667  events_injected=49  findings_created=5
    deterministic=True  wall_clock=262.33s

  TIMING CONSEQUENCE: against live Firestore the replay takes ~262s versus
  ~1-2s on the emulator (the gap is per-write network latency, not the
  pacing seam — raising --speed cannot remove it). The locked 65s beat-3
  budget therefore cannot contain a whole live replay; the take has to be a
  65s window of it.

  Cosmetic defect found: replay_cli.format_report hardcodes the string
  "(<240s budget)" onto duration_s, so it printed "262.33 (<240s budget)".

ENVIRONMENT NOTE (not a code defect)
------------------------------------
  `import vertexai` failed with an ImportError that looks like a circular
  import in aiplatform's trainingjob schema. Root cause was Windows
  MAX_PATH: the full path to
  ...definition_v1beta1/types/export_evaluated_data_items_config.py
  was 261 characters, one over the 260 limit, so Python could not open the
  file while os.listdir still reported it. Relocating the checkout to a
  short path (D:\dr) resolved it. Unchanged aiplatform version.
